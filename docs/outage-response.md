# 止まった・遅いときの記録と振り返り

サービスが止まった・遅い・エラーが増えたときに、何をどの順で残すかの型。乗っ取り・漏えいは [incident-response.md](./incident-response.md)、
「正常」の数字と、障害ごとに鳴るはずのアラートは [slo.md](./slo.md)。

予告なしの障害注入（カオスエンジニアリング、JUK-171）の練習と、本物の障害の両方で同じ型を使う。障害注入は平日 10〜22 時に
週2〜3回、予告なしで起きる（`CHAOS_SCHEDULE=on` のとき、JUK-176）。対応している間は、それが練習かどうかは分からない前提で動く。

## 流れ

1. アラートが鳴った・おかしいと気づいたら、[`outages/_template.md`](./outages/_template.md) を `outages/YYYY-MM-DD-短い名前.md` に写し、
   「対応中の記録」に時刻つきで書いていく。考えたことも、外れた予想も消さずに残す
2. 戻ったら（グラフが定常状態に戻ったら）、戻った時刻を書く
3. 障害注入の実験だったかは、そのあとで確かめる。実験が終わると運営者にメール（「障害注入の実験が終わりました」）が届き、
   管理者ページ（`/admin`）の「障害注入」に終わった実験が並ぶ
4. 同じファイルに「振り返り」を書く。決めた改善は Linear の Issue にする（障害に強くする改善は JUK-179 の子）
5. 分かったこと（まず見る場所・切り分け・戻し方）を、下の「アラートごとの手順」に足す

## 時間の測り方

| 名前 | 始まり | 終わり |
| -- | -- | -- |
| 気づくまで（MTTD） | 障害が始まった時刻 | 気づいた時刻（アラートのメールが届いた時刻か、自分で気づいた時刻の早い方） |
| 直るまで（MTTR） | 障害が始まった時刻 | 戻った時刻 |

- 障害が始まった時刻は、実験なら知らせのメールの「始めた」。本物の障害なら、グラフで最初に外れた時刻
- 実験が「終わる時刻が来て戻った」なら、自分で戻せていない。MTTR は「戻せなかった」と書き、気づいたかどうかだけを残す
- アラートが鳴らなかったら、それ自体が見つけた穴（slo.md の「障害とアラートの対応」と食い違う）。振り返りで直すものに入れる

## アラートごとの手順

**練習や本物の障害のあとに、分かったことを自分で書き足す。** 先に答えを書くと練習にならないので、最初は空にしてある。
アラートの中身（条件・しきい値）は `terraform/grafana/alerting.tf`。
